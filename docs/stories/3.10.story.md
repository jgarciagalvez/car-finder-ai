# Story 3.10: Translation Quality & Performance Improvements

## Status
Draft

## Story
**As a** user,
**I want** vehicles with required features mentioned only in descriptions to be correctly included in translation processing, and for translation to run concurrently for faster processing,
**so that** I don't miss good vehicle matches and can process translation batches efficiently.

## Context

This story addresses two critical translation pipeline improvements identified through user testing:

**Data Quality Issue (TD-022 - HIGH Priority):**
- Current problem: Vehicles are filtered as `not_interested` before translation when they lack required features in `sourceEquipment` (Polish feature list)
- User discovery: "Sometimes the car lists the A/C in the description, but not really in the features"
- Impact: Missing potentially good vehicles that mention required features (like A/C) in `sourceDescriptionHtml` but not in feature list
- Example: A vehicle with "klimatyzacja" (A/C) mentioned in Polish description gets filtered out incorrectly

**Performance Issue (TD-019 - MEDIUM Priority):**
- Current problem: Translation processes vehicles sequentially (one at a time), much slower than analyze script
- Current performance: 4 seconds per vehicle sequentially = very slow for large batches
- Desired behavior: Concurrent processing with p-limit (similar to analyze script) for 3x performance improvement
- Expected improvement: Process 3 vehicles concurrently while respecting 15 RPM rate limit

## Acceptance Criteria

### 1. Enhanced Feature Filtering with Description Search (TD-022)
- **AC1.1**: `hasRequiredFeatures()` function searches both `sourceEquipment` AND `sourceDescriptionHtml` for required feature keywords
- **AC1.2**: Polish A/C keywords searched in description: "klimatyzacja", "klimatyzacji", "klima", "AC", "A/C" (case-insensitive)
- **AC1.3**: Vehicle passes filter if required feature found in EITHER sourceEquipment OR description
- **AC1.4**: Vehicles with A/C in features list continue to pass (existing behavior preserved)
- **AC1.5**: Vehicles with A/C only in description now pass filter (new behavior)
- **AC1.6**: Vehicles with A/C in both sources pass filter
- **AC1.7**: Vehicles with no A/C in either source fail filter (existing behavior preserved)

### 2. Concurrent Translation Processing (TD-019)
- **AC2.1**: Add `concurrency` parameter to `TranslationOptions` interface (default: 3)
- **AC2.2**: Add `--concurrency` CLI flag to allow user control of concurrent processing
- **AC2.3**: Use p-limit library for concurrent processing (same pattern as analyze.ts)
- **AC2.4**: Process up to N vehicles concurrently (where N = concurrency parameter)
- **AC2.5**: Maintain 4-second delay between batches (not within batch) for 15 RPM rate limit compliance
- **AC2.6**: Concurrent processing uses Promise.all() for batch execution
- **AC2.7**: Progress tracking shows concurrent operations clearly

### 3. Error Handling & Backward Compatibility
- **AC3.1**: Failed vehicle translation doesn't block other concurrent operations
- **AC3.2**: Errors logged clearly with vehicle ID
- **AC3.3**: Script continues processing remaining vehicles on individual failures
- **AC3.4**: Comprehensive summary report at completion (success/failure/skipped counts)
- **AC3.5**: Script can still run with concurrency=1 for debugging (sequential mode)
- **AC3.6**: All existing functionality remains intact (--vehicle-id, --limit flags, etc.)
- **AC3.7**: No breaking changes to translation API or database schema

### 4. Testing Requirements
- **AC4.1**: Unit tests for enhanced `hasRequiredFeatures()` function:
  - Vehicle with A/C in features list (existing, should pass)
  - Vehicle with A/C in description only (new, should pass)
  - Vehicle with A/C in both (should pass)
  - Vehicle with no A/C anywhere (should fail)
- **AC4.2**: Unit tests for concurrent translation processing
- **AC4.3**: Integration test: concurrent translation respects rate limits
- **AC4.4**: Integration test: enhanced filtering correctly includes/excludes vehicles

### Architecture Context

#### Translation Script Architecture [Source: translate.ts]

**Current Translation Pipeline**:
```
1. Load vehicles needing translation (filter: description IS NULL)
2. For each vehicle:
   a. Check if vehicle has required features (hasRequiredFeatures())
   b. If NO required features → mark as 'not_interested' and skip translation
   c. If HAS required features → call AIService.translateVehicle()
   d. Save translation to database
   e. Wait 4 seconds (rate limiting)
```

**Current hasRequiredFeatures() Implementation** [Source: translate.ts:152-183]:
```typescript
private hasRequiredFeatures(vehicle: Vehicle): boolean {
  const requiredFeatures = this.criteria.mustHaveFeatures || [];
  if (requiredFeatures.length === 0) return true;

  // Only checks sourceEquipment (Polish feature list)
  for (const required of requiredFeatures) {
    const found = vehicle.sourceEquipment?.some(
      (feature) => feature.toLowerCase().includes(required.toLowerCase())
    );
    if (!found) return false;
  }
  return true;
}
```

**Problem**: This only checks `sourceEquipment`, not `sourceDescriptionHtml`.

**Solution**: Also search `sourceDescriptionHtml` for Polish keywords:
```typescript
private hasRequiredFeatures(vehicle: Vehicle): boolean {
  const requiredFeatures = this.criteria.mustHaveFeatures || [];
  if (requiredFeatures.length === 0) return true;

  for (const required of requiredFeatures) {
    // Check sourceEquipment (existing behavior)
    const foundInEquipment = vehicle.sourceEquipment?.some(
      (feature) => feature.toLowerCase().includes(required.toLowerCase())
    );
    if (foundInEquipment) continue; // Feature found, check next requirement

    // NEW: Check sourceDescriptionHtml for Polish keywords
    if (required.toLowerCase() === 'air conditioning') {
      const polishKeywords = ['klimatyzacja', 'klimatyzacji', 'klima', 'ac', 'a/c'];
      const foundInDescription = polishKeywords.some((keyword) =>
        vehicle.sourceDescriptionHtml?.toLowerCase().includes(keyword)
      );
      if (foundInDescription) continue; // Feature found in description
    }

    // Feature not found in either source
    return false;
  }
  return true;
}
```

#### Concurrent Processing Pattern [Source: analyze.ts:337-394]

**Analyze Script Concurrent Processing**:
```typescript
import pLimit from 'p-limit';

async run(options: AnalysisOptions): Promise<void> {
  const vehicles = await this.loadVehicles(options);
  const concurrency = options.concurrency || 3;
  const limit = pLimit(concurrency);

  // Process in batches
  const batchSize = concurrency;
  for (let i = 0; i < vehicles.length; i += batchSize) {
    const batch = vehicles.slice(i, i + batchSize);

    const promises = batch.map((vehicle) =>
      limit(() => this.analyzeVehicle(vehicle, options))
    );

    await Promise.all(promises);

    // Delay between batches (not within batch)
    if (i + batchSize < vehicles.length) {
      await this.delay(4000); // 4 seconds
    }
  }
}
```

**Translation Script Update Pattern**:

### Edge Cases & Error Scenarios

**Enhanced Filtering Edge Cases**:
1. **Multiple required features**: Vehicle must have ALL required features (in features OR description)
2. **Case variations**: "Klimatyzacja", "KLIMATYZACJA", "klimatyzacja" all match
3. **Keyword variations**: "klima", "AC", "A/C", "klimatyzacji" all match A/C requirement
4. **No description**: If `sourceDescriptionHtml` is null, fall back to `sourceEquipment` only
5. **Empty description**: Empty string treated same as null (only check features)

**Concurrent Processing Edge Cases**:
1. **Concurrency=1**: Sequential processing (existing behavior)
2. **Concurrency > available vehicles**: Process all vehicles in single batch
3. **Individual failure**: Log error, continue with remaining vehicles
4. **Network timeout**: Handle gracefully, don't block other operations
5. **Rate limit hit**: Script should handle 429 errors (unlikely with 4s delay)

### Risk Mitigation

**Data Quality Risk** (TD-022):
- **Risk**: May over-include vehicles (false positives)
- **Mitigation**: Keywords are A/C-specific, unlikely to match incorrectly
- **Rollback**: Revert hasRequiredFeatures() to original implementation

**Performance Risk** (TD-019):
- **Risk**: Concurrent processing may hit rate limits
- **Mitigation**: Default concurrency=3 is conservative (tested in Story 4.1)
- **Rollback**: Use `--concurrency 1` flag for sequential processing

**Integration Risk**:
- **Risk**: Breaking existing translation behavior
- **Mitigation**: Comprehensive unit and integration tests, backward compatibility checks
- **Rollback**: Feature flag or config to disable new behavior
