# Story 3.10: Translation Quality & Performance Improvements

## Status
Ready for Review

## Story
**As a** user,
**I want** vehicles with required features mentioned only in descriptions to be correctly included in translation processing, and for translation to use batch processing infrastructure for consistency,
**so that** I don't miss good vehicle matches and the translation script follows modern batch processing patterns.

## Context

This story addresses two translation pipeline improvements identified through user testing:

**Data Quality Issue - Filtering (TD-022 - HIGH Priority):**
- Current problem: Vehicles are filtered as `not_interested` before translation when they lack required features in `sourceEquipment` (Polish feature list)
- User discovery: "Sometimes the car lists the A/C in the description, but not really in the features"
- Impact: Missing potentially good vehicles that mention required features (like A/C) in `sourceDescriptionHtml` but not in feature list
- Example: A vehicle with "klimatyzacja" (A/C) mentioned in Polish description gets filtered out incorrectly
- **Solution**: Update `hasRequiredFeatures()` to search BOTH `sourceEquipment` AND `sourceDescriptionHtml`

**Infrastructure Modernization (TD-019 - Code Quality):**
- Current state: Translation script uses simple sequential loop, while analyze script uses modern p-limit batch processing
- Desired state: Both scripts use consistent batch processing infrastructure (even if concurrency=1 for translation)
- Benefits: Code consistency, easier maintenance, foundation for future optimization
- Rate limit safety: Default concurrency=1 ensures 15 RPM compliance (1 vehicle per 4s)

### Architecture Context

#### Translation Script Architecture [Source: translate.ts]

**Current Translation Pipeline**:
```
1. Load vehicles needing translation (filter: description IS NULL)
2. For each vehicle:
   a. Check if vehicle has required features (hasRequiredFeatures())
   b. If NO required features → mark as 'not_interested' and skip translation
   c. If HAS required features → call AIService.translateVehicle()
   d. Save translation to database
   e. Wait 4 seconds (rate limiting)
```

**Current hasRequiredFeatures() Implementation** [Source: translate.ts:152-183]:
```typescript
private hasRequiredFeatures(vehicle: Vehicle): boolean {
  const requiredFeatures = this.criteria.mustHaveFeatures || [];
  if (requiredFeatures.length === 0) return true;

  // Only checks sourceEquipment (Polish feature list)
  for (const required of requiredFeatures) {
    const found = vehicle.sourceEquipment?.some(
      (feature) => feature.toLowerCase().includes(required.toLowerCase())
    );
    if (!found) return false;
  }
  return true;
}
```

**Problem**: This only checks `sourceEquipment`, not `sourceDescriptionHtml`.

**Solution**: Also search `sourceDescriptionHtml` for required features from config:
```typescript
private hasRequiredFeatures(vehicle: Vehicle): boolean {
  const requiredFeatures = this.criteria.mustHaveFeatures || [];
  if (requiredFeatures.length === 0) return true;

  // Parse sourceEquipment
  let sourceEquipment: Record<string, string[]>;
  try {
    sourceEquipment = typeof vehicle.sourceEquipment === 'string'
      ? JSON.parse(vehicle.sourceEquipment)
      : vehicle.sourceEquipment;
  } catch (error) {
    return false;
  }

  const allPolishFeatures: string[] = Object.values(sourceEquipment).flat();

  // Check if vehicle has at least ONE required feature (ANY match)
  return requiredFeatures.some(requiredFeature => {
    const requiredLower = requiredFeature.toLowerCase();

    // Check in sourceEquipment (existing behavior)
    const foundInEquipment = allPolishFeatures.some(polishFeature =>
      polishFeature.toLowerCase().includes(requiredLower)
    );
    if (foundInEquipment) return true;

    // NEW: Check in sourceDescriptionHtml
    if (!vehicle.sourceDescriptionHtml) return false;
    return vehicle.sourceDescriptionHtml.toLowerCase().includes(requiredLower);
  });
}
```

**Key Improvements:**
- Uses `requiredFeatures` from `search-config.json` (10 klimatyzacja variations)
- No hardcoded Polish keywords
- Simple case-insensitive string search in description HTML
- Extensible - works for ALL required features, not just A/C

#### Concurrent Processing Pattern [Source: analyze.ts:337-394]

**Analyze Script Concurrent Processing**:
```typescript
import pLimit from 'p-limit';

async run(options: AnalysisOptions): Promise<void> {
  const vehicles = await this.loadVehicles(options);
  const concurrency = options.concurrency || 3;
  const limit = pLimit(concurrency);

  // Process in batches
  const batchSize = concurrency;
  for (let i = 0; i < vehicles.length; i += batchSize) {
    const batch = vehicles.slice(i, i + batchSize);

    const promises = batch.map((vehicle) =>
      limit(() => this.analyzeVehicle(vehicle, options))
    );

    await Promise.all(promises);

    // Delay between batches (not within batch)
    if (i + batchSize < vehicles.length) {
      await this.delay(4000); // 4 seconds
    }
  }
}
```

**Translation Script Update Pattern**:
```typescript
import pLimit from 'p-limit';

async run(options: TranslationOptions): Promise<void> {
  const vehicles = await this.loadVehicles(options);
  const concurrency = options.concurrency || 1; // Default: 1 for rate limit safety
  const limit = pLimit(concurrency);

  // Process in batches
  const batchSize = concurrency;
  for (let i = 0; i < vehicles.length; i += batchSize) {
    const batch = vehicles.slice(i, i + batchSize);

    const promises = batch.map((vehicle) =>
      limit(() => this.translateVehicle(vehicle, options))
    );

    await Promise.all(promises);

    // Delay between batches (4s delay with concurrency=1 = 15 RPM)
    if (i + batchSize < vehicles.length) {
      await this.delay(4000); // 4 seconds
    }
  }
}
```

### Edge Cases & Error Scenarios

**Enhanced Filtering Edge Cases**:
1. **Multiple required features**: Vehicle must have ALL required features (in features OR description)
2. **Case variations**: "Klimatyzacja", "KLIMATYZACJA", "klimatyzacja" all match
3. **Keyword variations**: "klima", "AC", "A/C", "klimatyzacji" all match A/C requirement
4. **No description**: If `sourceDescriptionHtml` is null, fall back to `sourceEquipment` only
5. **Empty description**: Empty string treated same as null (only check features)

**Concurrent Processing Edge Cases**:
1. **Concurrency=1**: Sequential processing (existing behavior)
2. **Concurrency > available vehicles**: Process all vehicles in single batch
3. **Individual failure**: Log error, continue with remaining vehicles
4. **Network timeout**: Handle gracefully, don't block other operations
5. **Rate limit hit**: Script should handle 429 errors (unlikely with 4s delay)

**Data Quality Risk** (TD-022):

**Integration Risk**:
