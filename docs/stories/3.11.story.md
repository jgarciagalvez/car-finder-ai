# Story 3.11: Fix Market Value Analysis Infinite Loop Bug

## Status
Draft

## Story
**As a** system administrator running analysis pipeline,
**I want** vehicles with insufficient market data to be marked as completed with `"insufficient_data"` value,
**so that** they don't get re-analyzed infinitely and block pipeline progress.

## Context

**Bug Discovery:**
- Discovered during Stories 4.1/4.2 analysis runs after Story 3.10 translation improvements
- Vehicles with insufficient market comparables (<3) get stuck in infinite analysis loop
- Script reports "✅ complete" in logs but "✅ Completed: 0" in summary

**Root Cause:**
- When `MarketValueService.calculateMarketValue()` returns `null` (insufficient comparables), nothing gets added to `analysis` object
- Line 699 in analyze.ts: `if (Object.keys(analysis).length > 0)` prevents completion tracking when analysis object is empty
- Vehicle stays with `marketValueScore = null` in database
- Next run: `findVehiclesNeedingAnalysis()` selects vehicle again (checks `IS NULL`)
- Result: Infinite retry loop

**Impact:**
- Vehicles with <3 comparables never complete analysis
- Get re-queued on every analysis run
- Block pipeline progress and waste compute resources
- Example: Ford Transit with 1/3 comparables processes repeatedly without completion

**Example Output:**
```
📋 Required steps: market_value
💰 Calculating Market Value Score...
⚠️ Insufficient comparables (1/3) for vehicle ddd122f2...
⚠️  Market Value: No comparables found (insufficient data)
✅ ddd122f2 complete [1/1]

Summary:
✅ Completed: 0  ← BUG: Should be 1
```

## Acceptance Criteria

### 1. Backend - Store Sentinel Value Instead of Null
- **AC1.1**: When `calculateMarketValue()` returns `null`, set `analysis.marketValueScore = "insufficient_data"`
- **AC1.2**: Vehicle gets saved to database with `marketValueScore = "insufficient_data"`
- **AC1.3**: Vehicle marked as completed (`this.runLog.vehiclesCompleted++` increments)
- **AC1.4**: `analysis` object is not empty (has marketValueScore field)
- **AC1.5**: Next analysis run skips vehicle (recognizes non-null marketValueScore)
- **AC1.6**: Existing vehicles with valid percentage scores (`"-5%"`, `"+10%"`, `"market_avg"`) remain unaffected

### 2. Database Query - Distinguish Null from Sentinel
- **AC2.1**: `findVehiclesNeedingAnalysis()` query still selects vehicles with `marketValueScore IS NULL`
- **AC2.2**: Query does NOT select vehicles with `marketValueScore = "insufficient_data"` (considers them analyzed)
- **AC2.3**: Backward compatible with existing null values (will retry those until they get sentinel value)
- **AC2.4**: Verify query uses `IS NULL` check (SQL), not equality check

### 3. Frontend - Display User-Friendly Message
- **AC3.1**: When `marketValueScore === "insufficient_data"`, display "No Data" in UI
- **AC3.2**: When `marketValueScore === null`, display "N/A" (not yet analyzed)
- **AC3.3**: When `marketValueScore` is percentage string (`"-5%"`, `"+10%"`, `"market_avg"`), display as-is
- **AC3.4**: Add tooltip/help text: "No Data = Not enough comparable vehicles found (minimum 3 required)"

### 4. Testing Requirements
- **AC4.1**: Unit test: Vehicle with <3 comparables gets `marketValueScore = "insufficient_data"`
- **AC4.2**: Unit test: Verify `analysis` object is not empty when sentinel value assigned
- **AC4.3**: Integration test: Re-running analysis skips vehicles with sentinel value
- **AC4.4**: UI test: `"insufficient_data"` renders as "No Data" with tooltip
- **AC4.5**: Manual test: Run `pnpm analyze` on problematic vehicles, verify completion counter increments

## Dev Notes

### Bug Analysis Context

**Affected Code Path:**
1. `analyze.ts:628` - Market value calculation step
2. `MarketValueService.calculateMarketValue()` returns `null` (insufficient comparables)
3. `analyze.ts:632-636` - Conditional check, nothing added to `analysis` object when null
4. `analyze.ts:699` - `if (Object.keys(analysis).length > 0)` → FALSE (empty object)
5. Vehicle never marked completed, stays in database with `marketValueScore = null`
6. Next run: `vehicleRepository.findVehiclesNeedingAnalysis()` selects it again

**Why This Is a Bug:**
- "Insufficient data" is a **valid analysis result**, not an incomplete analysis
- Vehicle **should** be marked completed with sentinel value indicating "analysis attempted, data unavailable"
- Current behavior: Treats "no data" same as "not analyzed" → infinite retry

**Design Decision:**
- Use sentinel string `"insufficient_data"` instead of keeping `null`
- Distinguishes three states:
  - `null` = Not yet analyzed (needs analysis)
  - `"insufficient_data"` = Analyzed but insufficient comparables (complete)
  - Percentage string = Analyzed with valid result (complete)

### File Locations

**Backend Files:**

- `apps/api/src/scripts/analyze.ts:699-713` - Completion tracking logic

### Technical Constraints

**Database:**
- Column already supports `string | null` type
- No migration needed
- Sentinel value is just another string value

**Backend:**
- TypeScript type already correct: `string | null`
- No type changes needed
- Backward compatible (existing null values will be updated on next analysis)

**Frontend:**
- Must handle three cases explicitly
- TypeScript strict mode requires proper type guards
- UI/UX consistency with existing "N/A" displays

### Edge Cases & Error Scenarios

**Edge Cases:**
1. **Vehicle initially has null → gets "insufficient_data" → more vehicles added later**
   - User can re-analyze with `--force` flag to override sentinel value
   - May now have enough comparables for valid percentage

2. **User manually resets value to null in database**
   - Will re-analyze on next run (expected behavior)
   - Allows manual retry if needed

3. **Vehicle has exactly 3 comparables (minimum threshold)**
   - Will get valid percentage score, not sentinel value
   - Threshold enforced by `MarketValueService` (config: `minComparables: 3`)

4. **All analysis steps return sentinel/null values**
   - Vehicle still marked completed (as long as `analysis` object not empty)
   - Each step adds its own field to `analysis` object

**Error Scenarios:**
1. **MarketValueService throws error (not returns null)**
   - Already handled: Line 638-654 catches errors, logs failure, re-throws
   - Vehicle NOT marked completed (correct behavior for true errors)

2. **Database save fails after setting sentinel value**
   - Caught by try-catch in calling code
   - Vehicle not marked completed (correct behavior)

### Risk Mitigation

**Risk: Breaking existing analysis pipeline**
- Mitigation: Minimal code change (one line), existing behavior preserved for valid scores
- Rollback: Revert line 635-636 change

**Risk: Frontend not handling new sentinel value**
- Mitigation: Add explicit case handling with fallback to "N/A"
- Testing: UI tests verify all three cases (null, sentinel, percentage)

**Risk: Query accidentally selects sentinel values**
- Mitigation: Verify query uses `IS NULL` (SQL), not string comparison
- Testing: Integration test confirms vehicles with sentinel not re-selected
