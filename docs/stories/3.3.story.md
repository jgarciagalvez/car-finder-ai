# Story 3.3: Multi-Level Sorting

## Status
Done

## Story
**As a** user,
**I want** to apply multiple sort criteria that stack together,
**so that** I can organize vehicles by priority while maintaining sub-sorting by other factors like price.

## Acceptance Criteria
1. Sorting system supports compound/stacked sorting:
   - Last applied sort becomes primary sort criterion
   - Equal values in primary sort are sub-sorted by previous sort criterion
   - Example: Sort by Priority (High→Low), then by Price (Low→High) = Vehicles primarily sorted by Price, but equal prices sub-sorted by Priority
2. Sort order persists ("fixed" once applied)
3. All existing sort options work with compound sorting:
   - AI Priority Rating
   - Personal Fit Score
   - Price
   - Year
   - Mileage
   - Date Added
   - Distance from Wrocław (from Story 3.2)
4. No visual UI indicator of sort stack (keep simple for MVP)
5. No "Clear all sorting" button (not needed for MVP)
6. Sort state persists during user session

**Single-Level Sort Function** (lines 118-173):
```typescript
export function sortVehicles(vehicles: Vehicle[], sortBy: SortOption): Vehicle[] {
  const sorted = [...vehicles]; // Create copy to avoid mutation

  sorted.sort((a, b) => {
    // Apply sort logic based on sortBy option
    switch (sortBy) {
      case 'priority':
        return (b.aiPriorityRating ?? b.personalFitScore ?? 0) -
               (a.aiPriorityRating ?? a.personalFitScore ?? 0);
      case 'price_asc':
        return a.priceEur - b.priceEur;
      // ... other cases
    }
  });

  return sorted;
}
```

**Key Patterns to Preserve**:
- Non-mutating: Always spread array before sorting
- Null handling: Use `?? 0` or `?? -1` for nullable fields
- Status handling: Push not_interested/deleted to end (priority sort only)
- Distance handling: Sort null distances to end (return 1 or -1)

#### Compound Sorting Algorithm [Source: Technical Design]

**Recommended Implementation**:
```typescript
export function sortVehiclesCompound(vehicles: Vehicle[], sortStack: SortOption[]): Vehicle[] {
  if (sortStack.length === 0) return vehicles;

  const sorted = [...vehicles];

  sorted.sort((a, b) => {
    // Apply sorts from end of stack (most recent = primary)
    // Iterate backwards through stack for tiebreaking
    for (let i = sortStack.length - 1; i >= 0; i--) {
      const comparison = compareVehicles(a, b, sortStack[i]);
      if (comparison !== 0) return comparison;
      // If equal, continue to next sort in stack (tiebreaker)
    }
    return 0; // All sorts equal, maintain stable order
  });

  return sorted;
}

function compareVehicles(a: Vehicle, b: Vehicle, sortOption: SortOption): number {
  // Extract comparison logic from current sortVehicles switch statement
  // Return negative (a before b), positive (a after b), or 0 (equal)
}
```

**Algorithm Explanation**:
- Stack: `['priority', 'price_asc']` means user sorted by priority first, then price
- Result: Primary sort = price_asc (most recent), tiebreaker = priority
- When prices are equal, use priority to determine order
- This is "last wins" behavior as specified in epic requirements

**New PUSH_SORT Action**:
```typescript
type VehicleAction =
  // ... existing actions ...
  | { type: 'PUSH_SORT'; payload: SortOption }
  // ...

case 'PUSH_SORT':
  // Remove duplicate if exists (prevent same sort stacking on itself)
  const filteredStack = state.sortStack.filter(s => s !== action.payload);
  // Add new sort to end (most recent = primary)
  const newStack = [...filteredStack, action.payload];
  // Limit stack size to 3 levels (prevent unbounded growth)
  const trimmedStack = newStack.slice(-3);
  return {
    ...state,
    sortStack: trimmedStack,
    sortBy: action.payload, // Update sortBy for UI display
  };
```

**Stack Management Rules**:
- Max 3 levels of sorting (reasonable limit for MVP)
- Duplicates removed before adding (user can't stack same sort twice)
- sortBy always reflects most recent selection (for dropdown display)

#### Performance Considerations

**Sorting Complexity**:
- Current: O(n log n) for single sort
- Compound: O(n log n) with O(k) comparison per pair (k = stack depth, max 3)
- Overall: O(n log n * k) which is still O(n log n) for small k
- Acceptable for ~200-300 vehicles

**Memory Usage**:
- sortStack adds minimal overhead (array of 1-3 strings)
- No additional vehicle copies (single sort operation)
- Spread operator creates one copy of vehicles array (same as current)
