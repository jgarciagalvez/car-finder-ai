# Story 3.5: Status Management - Comprehensive Update

## Status
Done

## Story
**As a** user,
**I want** clear status differentiation between system-processed vehicles and my workflow stages,
**so that** I can track which vehicles have been analyzed and manage my evaluation workflow effectively.

## Acceptance Criteria

### 1. Type Definition Update
- **AC1.1**: Update VehicleStatus type in `packages/types/src/index.ts`:
  ```typescript
  type VehicleStatus = 'new' | 'processed' | 'skipped' | 'to_contact' | 'contacted' | 'to_visit' | 'visited' | 'not_interested' | 'deleted'
  ```
- **AC1.2**: Add `isRemovedFromSource: boolean` field to Vehicle interface (default: false)

### 2. New Status Behaviors
- **AC2.1**: `new`: System-only status, assigned when vehicle is scraped, NOT visible in UI dropdown
- **AC2.2**: `processed`: User-facing status, indicates AI analysis is complete
- **AC2.3**: `skipped`: User-facing status, indicates user chose not to analyze (or to skip analysis)
- **AC2.4**: `isRemovedFromSource`: Boolean flag separate from status (for Story 3.7)

### 3. Database Schema
- **AC3.1**: Add new field: `isRemovedFromSource INTEGER DEFAULT 0` (SQLite boolean)
- **AC3.2**: Update status CHECK constraint to include new statuses
- **AC3.3**: Create database migration script
- **AC3.4**: Backfill: Update existing "new" vehicles to "processed" if they have AI analysis (aiPriorityRating != null)
- **AC3.5**: Backfill: Set all existing vehicles `isRemovedFromSource = 0`

### 4. UI Changes
- **AC4.1**: ~~Remove "New" from status dropdown options in VehicleCard~~ **REVISED**: Keep "New" visible in all status dropdowns for pipeline visibility (scraped-but-not-analyzed vehicles)
- **AC4.2**: Add "Processed" and "Skipped" to status dropdown
- **AC4.3**: Update status color and label utilities for new statuses
- **AC4.4**: Status dropdown order: New, Processed, Skipped, To Contact, Contacted, To Visit, Visited, Not Interested, Deleted

### 5. User Workflow
- **AC5.1**: Vehicle scraped → status = "new" (system-only)
- **AC5.2**: AI analyzes vehicle → status changes to "processed" (automatic via analyze script)
- **AC5.3**: User can manually set status to "skipped" if choosing not to analyze
- **AC5.4**: User workflow continues: `to_contact → contacted → to_visit → visited → not_interested → deleted`
- **AC5.5**: `isRemovedFromSource` flag is independent of status (set by Story 3.7 feature)

### Database Specifications
Current schema location: `packages/db/src/schema.ts`

Current status CHECK constraint:
```sql
status TEXT NOT NULL DEFAULT 'new' CHECK (status IN ('new', 'to_contact', 'contacted', 'to_visit', 'visited', 'not_interested', 'deleted'))
```
[Source: packages/db/src/schema.ts:110]

New column to add:
```sql
isRemovedFromSource INTEGER DEFAULT 0  -- SQLite uses 0/1 for boolean
```

**SQLite Limitation:** CHECK constraints cannot be modified in-place.

**DECISION: Use application-level validation ONLY.**
- Do NOT attempt to modify or recreate the CHECK constraint
- TypeScript type system will enforce valid status values at compile time
- The VehicleTable type union will prevent invalid values in code
- SQLite will accept any TEXT value, but TypeScript catches errors before runtime
- This is the standard MVP approach - simple and effective

**Why NOT recreate the table?**
- Risk of data loss
- Complex migration logic
- Downtime required
- Overkill for single-user local app
