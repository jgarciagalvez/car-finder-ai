#### Rate Limiting Strategy [Source: external-apis.md, Epic 4 Story 4.1 Context]

**Gemini API Rate Limits**:
- **Free Tier**: 15 RPM (requests per minute), 1M TPM (tokens per minute), 1,500 RPD (requests per day)
- **Critical Constraint**: 15 RPM = 1 request every 4 seconds
- **Current Utilization**: Sequential processing = 3.75 RPM (4 API calls per vehicle / 4 seconds = 1 call/second, but vehicles processed every 4s)

**Concurrent Processing Math**:
- **Current**: 1 vehicle × 4 calls = 4 calls every 4 seconds = ~60 calls/minute (if no delay) → EXCEEDS LIMIT
- **Current with delay**: 1 vehicle every 4 seconds = 15 vehicles/minute = 60 calls/minute → EXCEEDS LIMIT (but spread out)
- **Target**: 3-4 vehicles concurrently × 4 calls each = 12-16 calls every ~4 seconds = ~12-16 RPM → WITHIN LIMIT

**Concurrency Strategy**:
```
Concurrency=3 example:
- Batch 1: Process vehicles 1, 2, 3 concurrently (3 × 4 = 12 API calls in ~1-2 seconds)
- Wait 4 seconds (rate limit delay)
- Batch 2: Process vehicles 4, 5, 6 concurrently (3 × 4 = 12 API calls in ~1-2 seconds)
- Wait 4 seconds
- Continue...

Throughput: 3 vehicles every 4 seconds = 45 vehicles/minute → NO, THIS EXCEEDS RPM!

REVISED STRATEGY:
- Each vehicle makes 4 API calls sequentially (sanity, fit, mechanic, market, priority)
- BUT multiple vehicles can run concurrently
- With concurrency=3, 3 vehicles run in parallel, each making 4 calls sequentially
- If each vehicle takes ~4 seconds to complete all 4 calls (1s per call), then:
  - Batch of 3 vehicles completes in ~4 seconds
  - Each vehicle makes 4 calls over 4 seconds = 1 call/second per vehicle
  - 3 concurrent vehicles = 3 calls/second peak = 180 calls/minute → EXCEEDS LIMIT!

ACTUAL CORRECT STRATEGY:
- Gemini API has built-in rate limiting (handled by AIService retry logic)
- p-limit ensures max 3-4 vehicles process concurrently
- AIService already respects rate limits with retry/backoff (packages/ai)
- Concurrency=3 means 3 vehicles can START analysis concurrently
- AI service will naturally throttle if rate limit is hit (queuing internally)
- 4-second delay between BATCHES ensures we don't overwhelm the queue

Expected improvement:
- Current: 1 vehicle every 4s = 15 vehicles/min = 900 vehicles/hour (theoretical, but actual is slower due to API latency)
- Concurrent: 3 vehicles every ~10-15s (due to API latency + rate limits) = ~12-18 vehicles/min = ~720-1080 vehicles/hour
- Realistic: 3x-4x throughput improvement
```

**Important Notes**:
- AIService in `packages/ai` already has retry logic for rate limit errors [Source: packages/ai/src/utils/RateLimiter.ts, RetryHandler.ts]
- Concurrent execution should rely on AIService's built-in rate limiting
- p-limit ensures we don't queue too many concurrent operations
- 4-second delay between batches provides additional safety margin

#### Concurrency Control: p-limit Library [Source: Backend Architecture, Epic 4.1 Technical Notes]

**Why p-limit?**
- Clean API for limiting concurrent promise execution
- Better than Promise.all() for large datasets (avoids processing all at once)
- Handles queuing automatically (processes next vehicle as soon as slot opens)
- Simple integration with existing async/await code

**p-limit Usage Pattern**:
```typescript
import pLimit from 'p-limit';

// Create limiter with concurrency of 3
const limit = pLimit(3);

// Array of vehicles to process
const vehicles: Vehicle[] = [...];

// Wrap each analyzeVehicle call in limit()
const promises = vehicles.map((vehicle, index) =>
  limit(async () => {
    console.log(`Processing vehicle ${index + 1}/${vehicles.length}: ${vehicle.id}`);

    try {
      await this.analyzeVehicle(vehicle, options);
      this.stats.analyzed++;
      console.log(`✅ Vehicle ${vehicle.id} complete`);
    } catch (error) {
      this.stats.failed++;
      this.stats.errors.push({ vehicleId: vehicle.id, error: error.message });
      console.error(`❌ Vehicle ${vehicle.id} failed: ${error.message}`);
      // Don't re-throw - let other vehicles continue
    }
  })
);

// Wait for all vehicles to complete
await Promise.all(promises);
```

**Key Advantages**:
- Automatic queuing: As soon as one vehicle completes, next vehicle starts
- Graceful error handling: Failed promises don't affect others
- Progress tracking: Can log as each vehicle completes
- Configurable concurrency: Easy to adjust via flag

**Installation**:
- Package: `p-limit` (https://github.com/sindresorhus/p-limit)
- Version: Use v4.x for CommonJS compatibility (v5+ is ESM-only)
- Install command: `pnpm add p-limit --filter @car-finder/api`

#### Error Handling for Concurrent Execution [Source: analyze.ts lines 156-184, Coding Standards]

**Existing Error Handling**:
- Errors are caught per-vehicle in try-catch block
- Failed vehicles don't block remaining vehicles (`continue` statement)
- Errors logged to `stats.errors` array and `runLog.failures` array
- Error classification: `RateLimitError`, `AIError`, `ValidationError` (lines 156-184)

**Concurrent Error Handling Strategy**:
```typescript
const promises = vehicles.map((vehicle, index) =>
  limit(async () => {
    try {
      await this.analyzeVehicle(vehicle, options);
      this.stats.analyzed++;
      // Success logging
    } catch (error) {
      this.stats.failed++;
      this.runLog.vehiclesFailed++;
      const errorMsg = error instanceof Error ? error.message : 'Unknown error';
      this.stats.errors.push({ vehicleId: vehicle.id, error: errorMsg });

      // Log detailed failure to runLog
      this.runLog.failures.push({
        vehicleId: vehicle.id,
        vehicleTitle: vehicle.title,
        vehicleUrl: vehicle.sourceUrl,
        step: 'unknown', // Will be captured by analyzeVehicle
        error: errorMsg,
        errorType: getErrorType(error),
        timestamp: new Date(),
        retryable: isRetryableError(error),
      });

      console.error(`❌ Vehicle ${vehicle.id} failed: ${errorMsg}`);
      // Don't re-throw - allow other vehicles to continue
    }
  })
);

await Promise.all(promises);
```

**Key Points**:
- Each vehicle's promise has its own try-catch
- Failed promises don't reject the overall Promise.all()
- Stats and run logs are updated per failure
- Other vehicles in batch continue processing despite failures
