**API Client Pattern** [Source: Story 2.5 implementation]:
```typescript
// Pattern from translateVehicle/analyzeVehicle functions
export async function updateVehicle(
  vehicleId: string,
  updates: { status?: VehicleStatus; personalNotes?: string }
): Promise<Vehicle> {
  const response = await fetch(`${API_BASE_URL}/vehicles/${vehicleId}`, {
    method: 'PATCH',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(updates),
  });

  if (!response.ok) {
    if (response.status === 404) throw new Error('Vehicle not found');
    if (response.status === 400) throw new Error('Invalid update data');
    throw new Error('Update failed');
  }

  return await response.json();
}
```

#### UI/UX Guidelines [Source: PRD via Story 2.1, Story 2.5 QA]

**Design Goals**:
- **Inline Editing**: Status and notes editable directly on VehicleCard (no modal navigation)
- **Instant Feedback**: Optimistic UI updates for status changes
- **Clear States**: Loading, success, and error states for all async operations
- **Accessibility**: Keyboard navigation for dropdowns and inputs
- **Data Persistence**: All changes saved to database immediately (no "save all" button)

**Status Dropdown UX**:
- Dropdown trigger shows current status with color-coded badge
- Options display all 7 statuses with icons/colors for quick scanning
- On selection: Dropdown closes, loading indicator appears, then success/error feedback
- Consider grouping: Workflow statuses (new → contacted → visited) vs Archive statuses (not_interested, deleted)

**Notes Input UX**:
- Collapsed state: "Add notes..." placeholder or first 50 chars of existing notes
- Expanded state: Full textarea with "Save" and "Cancel" buttons
- Save triggers API call with loading state
- Auto-dismiss success message after 2-3 seconds
- Preserve unsaved changes with "Are you sure?" dialog if user navigates away (optional, advanced)

**Filter Controls UX**:
- Position filter controls next to sort controls in SearchAndFilters bar
- Multi-select pattern: Checkboxes in dropdown popover (similar to sort dropdown)
- Display active filter as badge: "Status: 3 selected" or "Status: new, to_contact, contacted"
- "Clear" button to reset filter (or "All Statuses" checkbox)

**Technology Stack**:

- **React**: ~18.3.0 with hooks (useState, useContext, useCallback)

**Coding Standards**:
- **Components**: PascalCase (`VehicleCard.tsx`)
- **Functions**: camelCase (`updateVehicle`, `setStatusFilter`)
- **Types**: PascalCase (`UpdateVehiclePayload`, `VehicleStatus`)
- **Props Interfaces**: ComponentNameProps pattern (`VehicleCardProps`)
- **Import Order**: React/Next → Third-party → Internal packages → Relative imports
- **Type Safety**: Explicit return types, no `any` types, strict null checks
- **API Client**: Centralized in `lib/api.ts`, consistent error handling pattern

**State Management Best Practices**:
- Use `useCallback` for functions passed to child components (prevent re-renders)
- Use `useMemo` for expensive filtering/sorting computations
- Avoid prop drilling: Use VehicleContext for shared state (status filter, vehicles array)
- Component-level useState for UI-only state (loading indicators, input values)
